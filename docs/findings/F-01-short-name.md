# F-01. Коротка назва

**Статус:** Temporarily accepted  
**Актив:** Облікові дані та дані локального PostgreSQ
**Компонент:** Конфігурація БД 
**Пріоритет:** P3

## Передумови і межі огляду

Commit, local environment, test account, reset command, endpoint/route та виключення.



Review-start commit: 20217548e3a421d6a36cb5bef0e87f0b725691db v0.5.0

Гілка: lab/6-hardening-review

Середовище: Windows, .NET SDK 10.0.401, PostgreSQL y Docker Compose

Обсяг: конфігурація локальної БД та файли, які вдствежує Git

Перевірка проводилася статично, без спроб несанкціонованого підключення до БД

Reset БД для цієї перевірки не потрібний і не виконувався



Фіксовані навчальні облікові дані PostgreSQL залишаються у відстежуваних Git файлах. Ризик тимчасово прийнято лише для локального навчального середовища SecureLab. Перед використанням застосунку поза локальним середовищем необхідно замінити навчальні облікові дані, налаштувати безпечне зберігання секретів і перевірити мережеві обмеження доступу до PostgreSQL.

## Відтворення

Нумеровані безпечні local-only кроки, expected та actual result.



1. Відкрити репозиторій SecureLab у локальному середовищі
2. Виконати пошук потенційно конфіденційних значень git grep -n -i -E 'password|secret|api.?key|connectionstring|token'
3. Перевірити збіги у файлах infra/compose.yaml; src/SecureLab.Api/appsettings.Development.json; src/SecureLab.Api/Data/SecureLabDesignTimeDbContextFactory.cs



Expected: Реальні секрети не зберігаються в Git. Навчальні значення обмежені локальним середовищем

Actual: У трьох відстежуваних файлах виявлено однакові фіксовані облікові дані PostgreSQL. У Readme.md зазначено їхнє призначення

## Вплив і ймовірність

**Статус перевірки:** спостережено локально 



Якщо облікові дані повторно використати в доступному ззовні середовищі, особа, яка знає ці значення, потенційно зможе спробувати підключитися до БД. У поточному локальному середовищі ризик обмежений призначенням конфігурації. Доступність PostgreSQL з інших пристроїв окремо не перевірялася

## Першопричина

Точний code/configuration decision, а не лише назва payload або symptom.



Для локального запуску SecureLab облікові дані PostgreSQL зафіксовано безпосередньо у Docker Compose, конфігурації Development та резервному рядку підключення EF Core. Це зручно, але створює ризик випадкового повторного використання однакових облікових даних в іншому середовищі

## Виправлення

Що змінено, чому це усуває причину; fixed commit або precise diff reference.



Конфігурацію не змінено, оскільки перевірка виконується в локальному середовищі. 

## Retest

Повторення початкового негативного сценарію після fix із фактичним результатом.



Повторне тестування після виправлення не виконувалося, оськільки ризик тимчасово прийнято і конфігурацію не змінено. Перед використанням SecureLab поза локальним середовищем потрібна повторна перевірка конфігурації

## Positive regression

Легітимний сценарій, який має лишитися робочим.



PostgreSQL успішно запущено через Docker Compose зі статусом Healthy

dotnet restore SecureLab.sln --locked mode завершився успішно

dotnet build SecureLab.sln -c Release --no-restore завершився успішно

dotnet test SecureLab.sln -c Release завершився успішно



## Залишковий ризик

Що control не покриває, що не тестувалося або яка умова лишається.



Фіксовані облікові дані залишаються у відствежуваних файлах. Ризик прийнятий лише за умови використання конфігурації для локального навчання. Для потрібне окреме налаштування секретів і мережевих обмежень
