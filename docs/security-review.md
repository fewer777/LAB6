# Security review SecureLab, ЛР 6

Рівень: достатній (Задовільно); Commit початку огляду (review-start): 20217548e3a421d6a36cb5bef9e76f0e87f0b725691db. 



1\. Executive summary

Один абзац: що перевірено, скільки знахідок зафіксовано й виправлено, результат фактичного фінального прогону, головні залишкові ризики.



Виконано початковий огляд безпеки SecureLab: перевірено середовище розробки, успішність збірки та автоматизованих тестів, конфігурацію застосунку й обробку HTTP-помилок у Production. Зафіксовано одну знахідку F-01 щодо використання фіксованих навчальних облікових даних PostgreSQL (пріоритет P3). Виправлених знахідок на поточному етапі немає. У Production підтверджено недоступність OpenAPI, заборону скидання бази даних, коректне формування відповідей 400, 401 і 500 у форматі ProblemDetails без розкриття внутрішніх деталей. Для помилки 500 встановлено відповідність traceId між HTTP-відповіддю та внутрішнім журналом сервера. Після відновлення штатного підключення до PostgreSQL запити GET /health і GET /api/incidents успішно повернули 200 OK. Залишкові ризики включають використання фіксованих навчальних облікових даних у локальному середовищі та неповну перевірку відповіді 404 для захищеного маршруту в Production без автентифікованого HTTPS-сеансу. 

## 2\. Scope та exclusions

Поточні відстежувані Git файли — обов’язково. Історія Git: лише фактично переглянуті файли, refs або проміжок дат; інакше напишіть «не перевірено».



Відстежування

* Поточні відстежувані Git файли проєкту, зокрема вихідний код API, конфігурацію, браузерний клієнт і Docker Compose.
* Налаштування Development та Production.
* Механізми автентифікації, авторизації та обробки HTTP-помилок.
* Перевірку наявності потенційних секретів у поточних відстежуваних файлах.
* Контрольовані перевірки поведінки API та відновлення нормальної роботи PostgreSQL.
* Регресійні перевірки SQLi, authentication, authorization/IDOR, XSS і CSRF у межах обраного рівня роботи.



Обмеження та виключення

* Повний аудит усієї історії Git не проводиться. Початкова точка огляду — commit 20217548e3a421d6a36cb5bef9e76f0e87f0b725691db.

Зовнішні production-сервери, хмарна інфраструктура та реальні облікові дані не входять до огляду.

* Перевірки проводяться в локальному навчальному середовищі.
* Повноцінне HTTPS-розгортання не перевірялося.
* Відповідь 404 для захищеного маршруту в Production не підтверджена: без автентифікації отримано 401 Unauthorized.



Розширені перевірки, передбачені лише для рівнів «Добре» та «Відмінно», не входять до обраного рівня.

## 8\. Hardening controls

Для всіх: наявні controls; наявний login limiter — повторна перевірка (quota, 429, відновлення), відсутній — gap або виключення з причиною. Добрий/відмінний: наявні headers, CORS, search limiter (два partitions, quota, 429, відновлення). CSP, якої не було, — N/A на достатньому/доброму; для відмінного вона обов’язкова й не має ламати client. Добрий/відмінний: змістові відмінності Development/Production. Відмінний: погодження advanced variant до реалізації й фактична перевірка; Redis — shared state, TTL, partition isolation, failure mode.

Зв’язок «control → ризик → фактична перевірка → межа»; у рядках про headers зазначте профіль, клієнт і status.
