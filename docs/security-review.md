Рівень: достатній (Задовільно); Commit початку огляду (review-start): 20217548e3a421d6a36cb5bef9e76f0e87f0b725691db.



1\. Executive summary

Один абзац: що перевірено, скільки знахідок зафіксовано й виправлено, результат фактичного фінального прогону, головні залишкові ризики.



Проведено локальний огляд безпеки SecureLab, перевірено конфігурацію Development і Production, обробку HTTP-помилок, механізми автентифікації та авторизації, SQLi, IDOR, XSS і CSRF. Зафіксовано одну знахідку F-01 — відсутність CSRF-перевірки під час створення інцидентів, яку виправлено в коміті a697e52. Повторне тестування підтвердило відхилення POST-запиту без CSRF-токена (400 Bad Request) та успішне створення інциденту з валідним токеном (201 Created). Автоматизовані тести завершилися успішно: 12 тестів пройдено. У Production підтверджено недоступність OpenAPI, заборону скидання бази даних та безпечну обробку HTTP-помилок. Основні залишкові ризики — використання навчальних облікових даних PostgreSQL у локальній конфігурації, неповна перевірка всіх операцій зміни даних на CSRF та відсутність повноцінного HTTPS-тестування. Фінальний прогін після злиття в main ще не виконувався.

## 6\. Detailed findings

Щонайменше одна власна знахідка для достатнього рівня, дві виправлені — для доброго; три виправлені — для відмінного, з них третя поза прямим checklist; кожна в окремому файлі docs/findings/\*.md.



Файл: docs/findings/F-01-missing-csrf-protection.md

У початковій реалізації POST /api/incidents не виконував перевірку CSRF-токена перед створенням запису.

Першопричина: відсутність перевірки IAntiforgery.IsRequestValidAsync у серверному обробнику.

Виправлення: коміт a697e52 (Lab6: CP-02), додано antiforgery-сервіси, endpoint отримання токена та перевірку перед створенням інциденту.

Retest: запит без CSRF-токена → 400 Bad Request, інцидент не створено.

Positive regression: запит із валідним токеном → 201 Created, інцидент створено.

Статус: Fixed

## 8\. Hardening controls

Для всіх: наявні controls; наявний login limiter — повторна перевірка (quota, 429, відновлення), відсутній — gap або виключення з причиною. Добрий/відмінний: наявні headers, CORS, search limiter (два partitions, quota, 429, відновлення). CSP, якої не було, — N/A на достатньому/доброму; для відмінного вона обов’язкова й не має ламати client. Добрий/відмінний: змістові відмінності Development/Production. Відмінний: погодження advanced variant до реалізації й фактична перевірка; Redis — shared state, TTL, partition isolation, failure mode.

Перевіряти всю історію не обов’язково — зазначте фактичні межі. Перевірки доброго рівня, які ви не виконували на достатньому, позначте «Не входить до обраного рівня», а не PASS.



Проведено пошук потенційних секретів у поточних відстежуваних файлах за ключовими словами password, secret, api key, connectionstring, token.

Виявлено фіксовані навчальні облікові дані PostgreSQL у локальній конфігурації, зокрема:

Класифікація: навчальні локальні значення конфігурації, не підтверджені як реальні production-секрети.

Рішення: залишено без змін у межах локального навчального середовища. Перед розгортанням поза локальним середовищем необхідно винести облікові дані до захищеної конфігурації.

Виявлення рядків, пов'язаних із токенами або паролями, не означає автоматично наявність витоку: частина збігів є назвами параметрів, типів або тестових значень.



## 10\. Residual risks

Неперевірені й тимчасово прийняті ризики, відповідальний і наступна дія.

Навчальні PostgreSQL credentials у конфігурації -> Тимчасово прийнято для локального середовища -> Розробник -> Винести секрети перед зовнішнім розгортанням



Неповна перевірка CSRF інших endpoints -> Не перевірено повністю -> Розробник -> Провести inventory і перевірити state-changing routes



Відсутність повноцінного HTTPS-тестування -> Не перевірено -> Розробник -> Перевірити cookies, HSTS і HTTPS redirection



Login rate limiting -> Поведінку не підтверджено -> Розробник -> Перевірити quota, 429 і відновлення



Автентифікований 404 у Production -> Не підтверджено -> Розробник -> Повторити з коректним HTTPS-сеансом
