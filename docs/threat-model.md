## Схема меж довіри

Невелика схема лише з компонентів, які у вас справді є (зразок — у PDF, етап 1, п. 2).    



Browser\["Браузерний клієнт SecureLab"] -> API\["ASP.NET Core Web API"] -> DB\[("PostgreSQL у Docker")] -> Repo\["Git-репозиторій"] -> Build\[".NET Build / Restore"] -> Env\["Змінні середовища та конфігурація"]



Browser -> |"HTTP-запити, cookie-сесія"| API

API -> |"Запити до БД"| DB

Repo -> |"Вихідний код і залежності"| Build

Env -> |"Налаштування запуску"| API



Browser -> API: недовірені запити з браузера переходять до серверної частини, яка повинна перевіряти автентифікацію, авторизацію та вхідні дані.

API -> PostgreSQL: сервер звертається до бази даних, забезпечуючи контроль доступу та захист від SQL-ін'єкцій.

Repository -> Build: вихідний код і залежності використовуються для формування виконуваного застосунку.

Environment -> Configuration: налаштування середовища визначають режим роботи застосунку та параметри підключення до БД.

## Очікувані властивості на межах

|Межа|Очікувана властивість (усі рівні)|Конкретний test або перевірка (добрий і відмінний)|
|-|-|-|
|browser→API|АРІ повинен перевіряти автентифікацію, авторизацію та коректність вхідних даних. Запити, які змінюють стан через cookie-сесію, повинні бути захищені від CSRF|Підтверджено відновлення роботи GET /api/incidents після повернення правильного підключення. Перевірки SQLi та IDOR заплановані.|
|API→PostgreSQL|Доступ до даних повинен виконуватися без, із дотриманням прав користувача|Підтверджено відновлення роботи GET /api/incidents після повернення правильного підключення. Перевірки SQLi та IDOR заплановані.|
|repository→build|Збірка повинна використовувати контрольовані залежності та не містити випадково збережених секретів|Успішно виконано dotnet restore --locked-mode, Release build і автоматизовані тести. Проведено початковий пошук потенційних секретів.|
|environment→configuration|Конфіденційні значення не повинні потрапляти до або повідомлень про помилки|Підтверджено Production-профіль, відхилення --reset-database, безпечний 500 ProblemDetails та збіг traceId із журналом сервера.|
