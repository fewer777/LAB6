## Схема меж довіри

Невелика схема лише з компонентів, які у вас справді є (зразок — у PDF, етап 1, п. 2).



Browser\["Браузерний клієнт SecureLab"] -> API\["ASP.NET Core Web API"] -> DB\[("PostgreSQL у Docker")] -> Repo\["Git-репозиторій"] -> Build\[".NET Build / Restore"] -> Env\["Змінні середовища та конфігурація"]



Browser -> |"HTTP-запити, cookie-сесія"| API

API -> |"Запити до БД"| DB

Repo -> |"Вихідний код і залежності"| Build

Env -> |"Налаштування запуску"| API



Browser -> API: Браузер передає HTTP-запити та дані користувача серверу. API повинен перевіряти автентифікацію, авторизацію, коректність вхідних даних і CSRF-токени для відповідних операцій зміни стану..

API -> PostgreSQL: Сервер взаємодіє з базою даних, у якій зберігаються користувачі та інциденти. Важливо запобігати SQL-ін'єкціям і несанкціонованому доступу до чужих записів.

Repository -> Build: Вихідний код, конфігурація та залежності використовуються під час збірки. Необхідно контролювати залежності та не допускати випадкового збереження реальних секретів у репозиторії.Environment -> Configuration: Змінні середовища та конфігураційні файли визначають режим роботи застосунку, параметри підключення до PostgreSQL і доступність службових функцій.

## Очікувані властивості на межах

|Межа|Очікувана властивість (усі рівні)|Конкретний test або перевірка (добрий і відмінний)|
|-|-|-|
|browser→API|Автентифікація, авторизація, валідація даних, захист від XSS і CSRF.|GET /api/me без автентифікації → 401. XSS-payload відображено як текст. POST /api/incidents без CSRF-токена → 400, із валідним токеном → 201.|
|API→PostgreSQL|Безпечна робота з даними, захист від SQLi, контроль доступу до записів.|Пошук q=O%27Brien успішний. Bob отримав 404 для чужого інциденту, Alice — 200 для власного. Після відновлення PostgreSQL API повернув 200.|
|repository→build|Контрольовані залежності, відтворювана збірка, відсутність випадково збережених production-секретів.|Успішні dotnet restore --locked-mode, Release build і 12 автоматизованих тестів. Проведено пошук потенційних секретів у поточних відстежуваних файлах.|
|environment→configuration|Безпечні налаштування Production, обмеження службових функцій, відсутність витоку внутрішніх деталей у помилках.|У Production /openapi/v1.json → 404, --reset-database відхилено, помилка БД → 500 ProblemDetails без stack trace. TraceId відповіді збігся із журналом.|

Відмінний рівень: у `docs/security-review.md` простежте для ключових активів зв’язок «актив → загроза → control → перевірка».
